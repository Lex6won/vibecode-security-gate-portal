# 서버 구축 절차서 — 공통 본문 + 환경별 부록 (2026-08-28)

> 이 문서 하나로 어떤 Windows 서버든 포털을 세울 수 있게 쓴다.
> **공통 본문**(§1~§6)은 집 테스트 서버와 기관 서버가 동일하고,
> 환경별 차이는 **부록 A(집 노트북)** / **부록 B(기관 서버)** 에만 있다.
> 집 세팅이 곧 기관 구축의 리허설이며, 이 문서는 이관 시 공식 구축 절차서가 된다.
>
> **비밀값 원칙**: 비밀번호·토큰·실제 주소는 이 문서와 저장소에 쓰지 않는다.
> 전부 `.env`(git 미추적)에만 두고, 문서에는 `<자리표시자>` 로만 쓴다.

## 1. 준비물

| 항목 | 용도 | 비고 |
|---|---|---|
| Node.js LTS | 포털 서버 | node --version 으로 확인 |
| Git | 소스 배포 | |
| Python 3.11+ | 체커(gvskb) | **Microsoft Store 파이썬 금지** — 스텁이라 동작 안 함. 서버는 **전용 venv 권장**(`C:\servers\checker-venv`) — 다른 프로젝트 의존성과 섞이지 않음 |
| nssm.exe | 서비스 등록 | https://nssm.cc 단일 exe. `C:\servers\tools\` 에 둠 |

설치 위치 원칙: **OneDrive 등 동기화 폴더 밖**. 권장 구조:

```text
C:\servers\
  vibecode-security-gate-portal\   ← 포털 (git)
  vibecode-checker\                ← 체커 (git)
  checker-venv\                    ← 체커 전용 파이썬 venv
  tools\nssm.exe
  portal-logs\                     ← 서비스 로그 (setup-server.ps1 이 저장소 상위에 만든다)
C:\portal-data\                    ← 데이터 (코드 밖 — git 배포가 못 건드림)
```

## 2. 소스·체커 설치

```powershell
cd C:\servers
git clone https://github.com/Lex6won/vibecode-security-gate-portal
git clone https://github.com/Lex6won/vibecode-checker

cd vibecode-security-gate-portal
npm ci

cd ..\vibecode-checker
py -3.11 -m venv C:\servers\checker-venv
C:\servers\checker-venv\Scripts\python.exe -m pip install -e .
C:\servers\checker-venv\Scripts\gvskb.exe doctor   # ERROR 없이 끝나야 함 (WARN 은 기록만)
```

**PATH 등록(필수)**: 포털은 PATH 의 `gvskb` 를 실행한다. 관리자 PowerShell 에서 체커 venv 의
Scripts 를 **시스템(Machine) PATH** 에 넣는다 — 사용자 PATH 에만 넣으면 LocalSystem 으로
도는 서비스가 체커를 못 찾는다.

```powershell
$venv = "C:\servers\checker-venv\Scripts"
$mp = [Environment]::GetEnvironmentVariable("Path","Machine")
if ($mp -notlike "*$venv*") { [Environment]::SetEnvironmentVariable("Path", ($mp.TrimEnd(";")+";"+$venv), "Machine") }
$env:Path = $env:Path.TrimEnd(";") + ";" + $venv
gvskb version
```

## 3. 서버 설정 (.env)

```powershell
cd C:\servers\vibecode-security-gate-portal
copy config\server.env.example .env
notepad .env
```

반드시 채울 것: `PORTAL_BIND_HOST=0.0.0.0`, `PORTAL_ALLOWED_HOSTS=<접속 주소>`,
`ADMIN_ID`/`ADMIN_INITIAL_PASSWORD`, 데이터 3경로(`C:\portal-data\...`).
각 항목 설명은 `config/server.env.example` 주석에 있다.

- 허용 호스트에 없는 주소로 들어온 요청은 421로 거부된다(기본 안전).
- `.env` 없이 켜면 로컬 전용(127.0.0.1)으로만 뜬다 — 개발 PC 기본 동작.

## 4. 서비스화 (상시 가동)

관리자 권한 PowerShell:

```powershell
cd C:\servers\vibecode-security-gate-portal
.\scripts\setup-server.ps1 -Port 8787
```

이 스크립트가 하는 일: 사전 점검(node·gvskb·.env) → 방화벽 인바운드(해당 포트,
Private 프로파일) → NSSM 서비스 등록(부팅 자동시작·비정상 종료 시 5초 후
재시작·로그 회전) → 전원 설정(절전 끔·덮개 닫아도 실행).

**서비스 환경 보정(필수)**: SCM 은 부팅 시점 환경을 캐시하므로 Machine PATH 변경이
서비스에 바로 반영되지 않을 수 있다. NSSM 에 직접 박아 둔다(등록 직후 1회):

```powershell
$svcPath = ([Environment]::GetEnvironmentVariable("Path","Machine")).TrimEnd(";")
& C:\servers\tools\nssm.exe set VibeCodePortal AppEnvironmentExtra "PATH=$svcPath" "PYTHONUTF8=1" "PYTHONIOENCODING=utf-8"
Restart-Service VibeCodePortal
```

**네트워크 프로파일 확인(필수)**: `setup-server.ps1` 의 방화벽 규칙은 **Private 프로파일 한정**이다.
연결된 망이 Public 으로 분류돼 있으면 규칙이 있어도 다른 기기에서 막힌다.

```powershell
Get-NetConnectionProfile                      # NetworkCategory 확인
Set-NetConnectionProfile -InterfaceIndex <n> -NetworkCategory Private
```

> 이 명령은 **관리자 권한 PowerShell** 에서만 된다. 일반 창에서 실행하면
> `Unable to set the NetworkCategory ... not running PowerShell elevated` 로 실패한다.
> (`powershell -File ...` 는 새 권한을 받지 않는다 — 창 자체를 "관리자 권한으로 실행"할 것)

수동 확인: `Get-Service VibeCodePortal` → Running. 로그: `C:\servers\portal-logs\portal.{out,err}.log`.

## 5. 배포와 롤백 (태그 단위)

서버는 `main`을 직접 받지 않고 **태그만** 배포한다. 개발 PC에서:

```powershell
git tag v0.3.0
git push origin v0.3.0
```

서버에서:

```powershell
.\scripts\deploy-server.ps1 -Tag v0.3.0     # 받기→검증→재시작→health 확인
.\scripts\deploy-server.ps1 -Tag v0.2.0     # 문제 시 이전 태그로 롤백 (같은 명령)
```

배포 스크립트는 문법·버튼 계약 검증에 실패하면 재시작 없이 중단한다.

## 6. 스모크 테스트 (세팅 완료 판정)

1. 서버 자신: `http://127.0.0.1:8787/health` → ok
2. 같은 망 다른 기기(휴대폰 등): `http://<서버IP>:8787` → 메인 화면
3. 점검 1건: 예제 폴더 업로드 → 간편 점검 → 보고서 저장까지
4. 재부팅 후 1~3 재확인 (서비스 자동 기동 검증)
5. 데이터 위치: 이력·계정·보고서가 `C:\portal-data\` 아래에만 생기고 코드 폴더(`.local\`, `reports\`)에는 안 생기는지

## 부록 A — 집 노트북 (테스트 서버)

**역할**: 동료 소규모 테스트 + 상시 검증. 시연은 이 노트북을 **지참**해 로컬 실행.

### A-1. 외부(도청 동료) 접속 — Cloudflare Tunnel + Access

업무 PC에는 아무것도 설치할 수 없으므로 브라우저 주소만으로 접속되게 한다.

1. Cloudflare 계정 + `cloudflared` 설치, 터널 생성 → `https://<터널 도메인>` 발급
2. **Access 정책**: 이메일 도메인 `gg.go.kr`, `korea.kr` 만 허용 (OTP 메일 인증)
3. `.env` 의 `PORTAL_ALLOWED_HOSTS` 에 `<터널 도메인>` 추가(포트 없이) 후 서비스 재시작
4. **운영 규칙**: ①실업무 소스 업로드 금지 안내를 화면·공지에 명시(테스트 데이터 전용)
   ②테스트 기간·시간에만 터널 가동 ③종료 시 터널 중지

> 트래픽이 해외 사업자 경유이므로 이 경로는 **화면·흐름 테스트 전용**이다.
> 실소스급 테스트가 필요해지면 직접 공개(DDNS+포워딩+Caddy TLS+도청 공인 IP
> 허용목록)로 전환한다 — 그 시점에 이 부록에 절차를 추가한다.

### A-2. 매직링크(P3 이후)

집 서버에는 메일 발송 경로가 없으므로 `.env` 로 개발 모드(링크 화면 표시)를 켠다.
(P3 구현 시 이 절에 변수명·절차 확정)

## 부록 B — 기관 서버 (운영, 확정 대기 항목 포함)

**전제**: 인터넷망 배치(체커 조회 필요). 반입은 망연계 **파일전송**만 가능.

### B-1. 릴리스 번들 반입 (git 대신)

개발 PC(외부망)에서:

```powershell
.\scripts\build-release-bundle.ps1 -Tag v0.3.0
# → dist\portal-bundle-v0.3.0.zip + .sha256 (전체 해시)
```

번들 내용: 소스 스냅샷(git archive) + node_modules(오프라인 의존성) +
파일별 SHA-256 매니페스트(MANIFEST.sha256, 태그·커밋·생성시각 포함).

반입 절차: ZIP+`.sha256` 함께 전달 → 반입 후 `Get-FileHash` 로 전체 해시 대조 →
압축 해제 → MANIFEST 로 파일별 무결성 확인 → §3~§6 공통 절차 수행
(§2의 git clone 은 생략, §5의 git 배포 대신 새 번들 반입으로 갱신).

체커·Node·Python 설치본도 최초 1회 같은 방식으로 반입한다
(체커는 pip wheel 오프라인 묶음: `pip download -d wheels .` → 반입 → `pip install --no-index --find-links wheels`).

### B-2. 확정 대기 항목 (확정되면 이 절 갱신)

| 항목 | 상태 | 영향 |
|---|---|---|
| 서버 OS | 미정 | Linux 확정 시 ZIP 사전검사의 PowerShell 의존을 Node 구현으로 교체 + 본 절차서 명령 전면 수정 |
| SMTP 발송 경로 | 미협의 | P3 매직링크 실발송. 확정 전엔 개발 모드만 |
| 접속 도메인·TLS | 미정 | `PORTAL_ALLOWED_HOSTS` 값, 기관 인증서 |
| 서버 자원 | 미정 | `PORTAL_MAX_CONCURRENT_SCANS` 등 용량 값 |
| 보고서 보존기한 | **구현됨(기본 90일)** | `PORTAL_REPORT_RETENTION_DAYS` 값만 정책에 맞게 조정 — 화면 고지·자동 삭제가 함께 바뀜 |
