# 로컬 하네스 시험운영

작성일: 2026-09-13

## 지금 가능한 것

현재 PC에서는 포털이 로컬 시험용 하네스 설치파일을 직접 제공한다.

```powershell
cd C:\coding\vibecode-security-gate-portal
npm run start:pilot
```

콘솔에 표시되는 `http://127.0.0.1:<포트>`로 접속한다. 일반 `npm start`는 기존처럼 외부 HTTPS 배포 정보를 사용하고, `start:pilot`만 저장소에서 제외된 `local-artifacts/harness/release-index.json`을 사용한다.

로컬 설치파일은 다음 조건을 모두 만족해야 다운로드된다.

- 포털이 `127.0.0.1`, `localhost` 또는 `::1`에 바인딩됨
- 설치파일이 release-index와 같은 폴더에 있음
- 안전한 `.exe` 파일명임
- release-index의 SHA-256과 실제 파일의 SHA-256이 같음

화면과 API는 이 파일을 `local_test_installer_ready`, `unsigned_local_test`, `is_demo: true`로 표시한다. 정식 배포본이나 기관 승인본으로 표시하지 않는다.

## 저장소에 넣지 않는 시험 자료

`local-artifacts/` 전체는 `.gitignore` 대상이다. 시험 설치파일, release-index, 로컬 시험 개인키는 Git에 커밋하지 않는다. 특히 `C:\work\vibecode-local-release\keys\local-test-private.pem`은 운영 서명에 재사용하지 않고 시험 종료 후 폐기한다.

## 서버 설치 뒤 반드시 할 일

다음 항목이 끝나기 전에는 운영 승인 또는 정식 배포라고 부르지 않는다.

1. 체커와 하네스의 승인 커밋을 immutable tag로 고정하고 깨끗한 CI 빌드에서 다시 만든다.
2. 체커 wheel·독립 EXE·하네스 번들의 SBOM과 SHA-256을 발급한다.
3. 기관용 Ed25519 서명키를 개발 PC 밖의 보호된 저장소/HSM에서 만들고 공개키만 신뢰목록에 배포한다.
4. 기관 코드서명 인증서로 설치 EXE에 Authenticode 서명하고 신뢰할 수 있는 타임스탬프를 붙인다.
5. 서명·해시·SBOM·검토자·승인일을 release approval record에 남긴다.
6. HTTPS 배포 위치에 정식 설치파일과 release-index를 게시한다. 포털은 그 HTTPS 주소만 사용하게 전환한다.
7. 서버에 `PORTAL_EXPECTED_CHECKER_COMMIT`과 승인된 인텔 번들 출처를 고정한다.
8. 깨끗한 Windows PC에서 설치, 네 도구 재시작, MCP 도구 조회, npm/PyPI 차단, Python/JavaScript/TypeScript 허용, 미허용 언어 차단을 다시 검증한다.
9. 승인 Windows CI runner와 보호 브랜치 필수 체크를 켜고 업데이트·롤백·키 폐기 시나리오를 시험한다.
