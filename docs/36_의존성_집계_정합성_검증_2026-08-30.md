# 36. 의존성 결과 집계 정합성 검증 (2026-08-30)

## 문제

점검 결과 화면은 `의존성 취약점 0건`으로 표시했지만, 같은 점검의 HTML 리포트는 `remotion 4.0.252`을 포함한 취약 패키지 7종을 보고했다.

## 원인

체커 `gvskb 0.3.0`의 JSON 형식에서 의존성 위험은 다음 위치에 있다.

```text
dependency_audit.audits[].checks[]
```

각 `check`의 `verdict`, `vulnerability_count`, `requires_review`가 판정 근거다. 포털은 존재하지 않는 `dependency_audit.summary.finding_count`를 읽고 있었으므로 0으로 떨어졌다.

## 수정 기준

- `취약 패키지 수`: 취약 판정인 고유 `(생태계, 이름, 버전)` 수
- `취약점 권고 수`: 같은 고유 패키지의 `vulnerability_count` 합계
- `검토 신호 수`: `requires_review=true`인 고유 패키지 수
- 동일 패키지가 lockfile과 manifest에 중복돼도 취약 패키지는 한 번만 센다.
- 과거 이력도 서버 시작 시 보관된 JSON 산출물을 다시 읽어 메모리상 요약값을 보정한다. 원본 산출물과 이력 원본은 수정하지 않는다.

## 검증

`Docufinder` 표준 점검(`d4e17786-e76a-46fe-98c5-91477666982b`)의 보관 JSON으로 확인했다.

| 항목 | 값 |
| --- | ---: |
| HTML 리포트의 취약 패키지 | 7종 |
| 포털 API `dependency_finding_count` | 7 |
| 포털 API `dependency_advisory_count` | 13 |
| 포털 API `dependency_review_count` | 9 |

회귀 검증은 `scripts/scan-summary-test.mjs`가 맡고 `npm run check`에 포함한다.
