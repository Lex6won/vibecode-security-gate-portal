## 0. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 디자인 토큰 | `design/html-prototype-v2/shared.css` 의 CSS 변수만 사용. 값 직접 입력 금지 |
| 서체 | Pretendard → Noto Sans KR → Malgun Gothic 순 fallback. **CDN 금지, self-host** |
| 줄바꿈 | `word-break: keep-all` 유지 (한국어 어절 단위) |
| 최대 폭 | 1180px |
| 외부 리소스 | 없음. 이미지·서체·스크립트 전부 self-host |
| 상태 표현 | 색만으로 구분하지 않는다. 아이콘·텍스트를 함께 둔다 |
| 금지 표현 | 판정 불가·검사 0건·오래된 정보를 **"안전"으로 표시하지 않는다** |
| 경로 노출 | 결과 API는 전체 경로 대신 폴더 라벨만 반환 |

**화면 소유 구분** — 같은 디자인 언어를 쓰지만 제공 주체가 다르다.

| 화면 | 제공 | 비고 |
|---|---|---|
| 첫 화면, 개발 기준, 맛보기 점검, 승인 화면 | 경기도 내부 서버 | 브라우저 |
| 점검 실행, 설치·업데이트, MCP 연결 | **로컬 에이전트** | 에이전트가 직접 서빙(same-origin) |

중앙 서버 화면은 **어떤 경로로도 `127.0.0.1` 을 호출하지 않는다.**

## 1. 첫 화면 (`index.html`)

### 목적
설치를 첫 관문으로 두지 않는다. 지금 바로 할 수 있는 것을 맨 앞에 둔다.

### 구성
1. 상단바 — 로고, "검사는 내 PC에서만" 상시 표시
2. 히어로 — 대표 행동 2개(개발 기준 받기 / 맛보기 점검). **설치 버튼이 히어로에 없다**
3. 3단 카드 — STEP 1(설치 없음) → STEP 2(1회 설치) → STEP 3(선택)
4. 에이전트 상태 스트립
5. 데이터 보호 안내 + 현재 적용 기준 버전

### 상태 규칙

| 에이전트 상태 | 스트립 표시 | STEP 2 버튼 |
|---|---|---|
| 미설치(기본) | 회색 점 + "설치되지 않았습니다" | `설치 파일 받기` |
| 설치됨 | 초록 점 + 버전 표시 | `점검 화면 열기` |

**서버는 설치 여부를 탐지하지 않는다.** 브라우저가 로컬을 조회하는 구조를 만들지 않는다. 기본은 미설치로 두고, 설치 관리자가 완료 시 로컬 UI를 자동으로 연다.

### STEP 3 처리
지원 AI 도구 미확인이 기본값. 카드를 `.muted` 로 흐리게 하고 버튼을 비활성화하되, **결핍이 아니라 선택 사항**으로 읽히는 문구를 쓴다.
> "이 기능은 위 도구를 쓰는 경우에만 필요합니다. 없어도 1·2번은 모두 사용할 수 있습니다."

### 연결 API
- `GET /api/channel/manifest?channel=stable` → 현재 승인 버전 표시
- 설치 파일 다운로드 링크(3종)

## 2. 개발 기준 열람 (`harness.html`)

### 목적
하네스는 실행 프로그램이 아니라 파일 묶음이다. **Python·AI 없이 완결**되는 유일한 기능이므로 T0의 중심에 둔다.

### 구성
- 상단 내려받기 카드: 버전, 승인일, 파일 수, 크기, **SHA-256 전문 표시**
- 좌: 역할별 3묶음 아코디언 / 우: 읽기 전용 뷰어

### 파일 묶음 규칙

| 묶음 | 대상 | 기본 상태 |
|---|---|---|
| ① 내가 지켜야 할 개발 기준 | 공무원 본인 | **펼침** |
| ② AI 도구가 읽는 파일 | AI 도구 사용자 | 접힘 |
| ③ 기관이 정한 정책 | 담당·검토자 | 접힘 |

- 모든 파일에 **"이 파일이 하는 일" 한 줄 설명**을 붙인다. 원문만 보이면 첫 화면에서 이탈한다.
- **편집·저장 기능을 만들지 않는다.** 기관 표준이 사용자별로 갈라지면 존재 이유가 없어진다. 화면에 그 이유를 명시한다.
- 적용 안내는 한 문장으로 끝낸다: "압축을 풀어 프로젝트 폴더에 넣으면 적용됩니다."

### 연결 API
- `GET /api/harness/tree?bundle=<id>` — 목록·묶음·설명
- `GET /api/harness/file?bundle=<id>&path=<p>` — **manifest에 등재된 경로만 허용.** 임의 경로를 파일시스템에 전달하지 않는다
- `GET /api/harness/archive?bundle=<id>` — ZIP + SHA-256

## 3. 맛보기 점검 (`precheck.html`)

### 목적
설치 전에 가치를 체감시키되 **소스 미전송 원칙을 깨지 않는다.**

### 필수 구현 조건

| 항목 | 규칙 |
|---|---|
| CSP | 이 페이지만 **`connect-src 'none'`** 로 제공한다 |
| 경로 분리 | 텔레메트리·API를 쓰는 화면과 **다른 경로**에 둔다 |
| 검사 엔진 | 브라우저 JavaScript. 파일 내용은 탭 메모리에만 존재 |
| 규칙 범위 | 정규식으로 확정 가능한 것만 (하드코딩 비밀값, API 키, 개인정보 패턴) |
| 규모 상한 | 파일 100개 · 총 5MB. 초과 시 정식 점검 안내 |
| 산출물 | **파일 보고서를 발급하지 않는다** |
| 결과 성격 | positive-only. "발견되면 문제, 없어도 안전 아님" |

### 화면 요소
- 상단 상시 배지: `🔒 네트워크 요청 0건`
- 전송 차단 설명 박스 — "약속이 아니라 기술적으로 불가능한 상태"
- 결과 옆에도 동일 배지 반복
- **하단 고정 배너**: "맛보기 점검입니다. 제출·배포 판단에 쓸 수 없습니다"

### 검증 요건
CSP 위반 이벤트를 수집해 **검사 중 네트워크 요청이 0건임을 자동 테스트로 증명**한다(수용 기준 16).

## 4. 승인 화면 (`admin-approval.html`)

### 목적
정보보안팀이 **코드를 읽지 않고** 판단할 수 있어야 한다. 부담이 큰 절차는 반드시 형식화된다.

### 정보 위계 (이 순서를 바꾸지 않는다)
1. **오늘 할 일이 몇 건인가** — 확인 필요 건수를 가장 크게
2. 자동 처리된 건수 (확인 불필요임을 명시)
3. 현재 적용 중인 자동 승인 정책
4. 개별 건 상세

### 개별 건 상세에 반드시 있어야 하는 6개 항목

| 순서 | 항목 | 비고 |
|---|---|---|
| 1 | **외부 패키지 변경** | 승인자가 가장 먼저 보는 것. 신규 추가는 강조 |
| 2 | 자동 검증 결과 | 테스트 건수 |
| 3 | 체커 자기검사 | 차단 항목 수 |
| 4 | 반대 방향 검증 | 새 오탐·미탐 여부 |
| 5 | 개발자 서명 | 검증 여부·시각 |
| 6 | 전달 중 변조 여부 | 해시 대조 |

- **자동 승인되지 않은 이유를 명시**한다. "왜 나에게 왔는가"를 승인자가 추측하게 하지 않는다.
- 동작은 `승인` / `보류(질의)` / `반려` 세 가지.
- 승인 시 결과를 예고한다: "경기도 배포 키로 서명 → 일부 PC 우선 배포 → 이상 없으면 전체".

### 사이드 패널
- 대기 목록 (자동 처리 건은 올라오지 않는다는 안내 포함)
- 최근 자동 승인 이력 (분기 감사용)
- 배포 현황 + 자동 회수 안내

### 접근 통제
- 기관 SSO/OIDC 인증 필수. **자체 ID·비밀번호 구현 금지**
- 텔레메트리 엔드포인트로는 조회 불가

## 5. 기존 화면 재사용·수정

| 기존 파일 | 처리 |
|---|---|
| `security-scan.html` | **재사용.** 저장 위치 선택 필수 규칙, 진행률 단계 표기 유지 |
| `skill-harness.html` | **수정.** 상태를 §5.3의 6개(미설치/최신/업데이트필요/비공식/검증실패/판정불가)로 확장. `git` 기반 표기 삭제 |
| `admin.html` / `admin-login.html` | **폐기.** 자체 로그인은 정책 위반. 승인 화면 + OIDC로 대체 |

### MCP 연결 화면 추가 요건
등록 버튼만 있으면 안 된다. **`등록` / `해제` / `복원` 세 동작**을 모두 노출하고, 백업 시점 목록에서 되돌릴 수 있어야 한다.

## 6. 반응형·접근성

- 900px 이하에서 2단 레이아웃은 1단으로 전환한다.
- 표는 `.tbl` 래퍼로 가로 스크롤시킨다. **body가 가로로 스크롤되지 않게 한다.**
- 모든 상태 배지는 아이콘 + 텍스트를 함께 쓴다.
- 아코디언·탭은 키보드로 조작 가능해야 하며 `aria-expanded` / `aria-selected` 를 갱신한다.
- 대비는 본문 4.5:1 이상.

## 7. 화면별 완료 기준

| 화면 | 완료 기준 |
|---|---|
| 첫 화면 | 에이전트 미설치 상태에서 STEP 1의 두 기능이 모두 동작한다 |
| 개발 기준 | 설치 없이 ZIP을 받아 프로젝트에 적용할 수 있고, SHA-256이 화면에 표시된다 |
| 맛보기 점검 | 검사 중 네트워크 요청 0건이 자동 테스트로 증명되고, 보고서 파일이 생성되지 않는다 |
| 승인 화면 | OIDC 없이 접근 불가하고, 자동 승인 미적용 사유가 항상 표시된다 |
