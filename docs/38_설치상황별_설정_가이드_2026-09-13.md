# 38. 설치 상황별 설정 가이드 — 포털·체커·인텔 (2026-09-13)

목적: 포털을 어디에 어떻게 설치했는지에 따라 **무엇을 바꿔야 하는지** 한 장으로 정한다.
운영자는 1절의 질문에 답하고, 2절에서 자기 상황(A~D)을 고른 뒤, 3절의 그 상황 열만 적용한다.
이 문서는 설정을 "정리"하는 문서이며, 서버 이전 시점의 실행 항목은 하네스 docs/25 체크리스트가 관리한다.

## 1. 먼저 답할 질문 (운영자 → 담당자)

| # | 질문 | 답이 정하는 것 |
|---|---|---|
| Q1 | 포털이 도는 곳은? (이 PC 시범 / 기관 서버 / 집 노트북 서비스) | 바인드 주소, 서비스 계정, 캐시 경로 |
| Q2 | 서버에서 **github.com** 에 나갈 수 있는가? | 인텔 번들 자동 당김 가능 여부 |
| Q3 | 서버에서 **정부 깃랩(gitlab.aigov.go.kr)** 에 나갈 수 있는가? | 번들 미러 경로, 점검 대상 저장소 URL |
| Q4 | 서버에서 **pypi.org · registry.npmjs.org** 에 나갈 수 있는가? | 패키지 실재·발행일(쿨다운) 판정 가능 여부 |
| Q5 | 서버에서 **osv.dev · services.nvd.nist.gov · knvd.krcert.or.kr** 에 나갈 수 있는가? | 없어도 된다(번들이 대신). 있어도 서버가 직접 부르지 않는다 |
| Q6 | 외부 사용자(터널·Access)를 받는가, LAN/로컬만인가? | 인증 모드, 허용 호스트, Access 변수 |
| Q7 | 체커를 어떻게 설치했는가? (editable 소스 연결 / wheel) | 예상 커밋 값과 확인 방법 |

## 2. 상황 분류

| 상황 | 조건 | 지금 어디에 해당 |
|---|---|---|
| **A. 시범 PC** | Q1=이 PC, Q2~Q5 모두 가능 | 현재(집 노트북 NSSM 서비스 + 개발 클론) |
| **B. 인터넷 제한 서버** | GitHub 가능, OSV/NVD/KNVD 불가, PyPI/npm 은 선택 | 기관 서버 1차 예상 |
| **C. 깃랩만 가능한 서버** | GitHub 불가, 정부 깃랩 가능 | 기관 내부망 예상 |
| **D. 완전 망분리** | 외부 전부 불가, USB 반입만 | 폐쇄망 |

핵심 원칙: 서버는 **NVD·KNVD·OSV 에 직접 붙지 않는다.** GitHub Actions 가 매일 받아 검증한 번들(`intel-latest`, 7개 소스) 하나만 받는다. 판정은 번들의 로컬 캐시로 한다.

## 3. 상황별 설정 매트릭스

### 3-1. 체커(gvskb) 환경변수 — 서비스 계정에 적용(NSSM `AppEnvironmentExtra` 또는 시스템 환경변수)

| 변수 | A. 시범 PC | B. 인터넷 제한 서버 | C. 깃랩만 | D. 망분리 |
|---|---|---|---|---|
| `GVSKB_MODE` | 미설정(온라인) | `offline` | `offline` | `offline` |
| `GVSKB_CACHE_DIR` | `C:\Users\User\.gvskb\cache` (서비스가 사용자 캐시 공유) | `C:\servers\gvskb-cache` | 좌동 | 좌동 |
| `GVSKB_INTEL_DIR` | 미설정 | `C:\servers\intel-inbox` | 좌동 | USB 반입 폴더 |
| `GVSKB_INTEL_URL` | 미설정(기본 GitHub) | 미설정(offline 에서는 URL 을 쓰지 않는다) | 미설정 | 미설정 |
| `GVSKB_AUTO_UPDATE` | 기본(on) | on | on | on (폴더만 본다) |
| `GVSKB_INTEL_MAX_AGE_DAYS` | 기본 30 | 30 | 30 | 기관 정책(예: 45) |
| `NVD_API_KEY` | 서버에 **불필요** (GitHub Actions secret 에만) | 불필요 | 불필요 | 불필요 |

번들 공급 방식:

| | A | B | C | D |
|---|---|---|---|---|
| 번들 출처 | GitHub `intel-latest` 자동 당김 | GitHub → 예약 작업이 inbox 에 저장 | 정부 깃랩 미러 → 예약 작업이 inbox 에 저장 | 외부망 PC 에서 받아 USB 로 inbox 에 복사 |
| 반입 트리거 | MCP 서버 기동·`gvskb intel-sync` (하루 1회 스로틀) | 예약 작업 04:00: 다운로드 → sha256 확인 → `gvskb intel-sync` | 좌동 | 반입 후 `gvskb intel-sync` 수동 |
| 미러 유지 | — | — | GitHub Actions 에 깃랩 업로드 단계 추가(토큰 필요) | — |

주의(현재 코드): `GVSKB_MODE=offline` 이면 자동 당김은 **폴더만** 시도하고 URL 은 시도하지 않는다(망분리 원칙). 그래서 B·C 는 "다운로드는 예약 작업이, 반입은 체커가" 나눠 맡는다. 포털이 부르는 `gvskb scan` 자체는 자동 당김을 트리거하지 않는다 — 다음 라운드 보완 후보.

### 3-2. 포털 `.env` — 서버 폴더(`C:\servers\vibecode-security-gate-portal\.env`)

| 변수 | A. 시범 PC | B/C. 서버 | D. 망분리 |
|---|---|---|---|
| `PORTAL_BIND_HOST` | 현재 값 유지(LAN/터널용) | 서버 IP 또는 `0.0.0.0` | LAN IP |
| `PORTAL_ALLOWED_HOSTS` | 터널 호스트명 포함 | 서버 호스트명·IP | LAN 호스트명 |
| `PORTAL_EXPECTED_CHECKER_COMMIT` | `b27fccacf77c602800f70cf1e62bfde3ec8e2e4a` | 배포한 wheel 의 build_commit | 좌동 |
| `PORTAL_AUTH_MODE` | 개발(미설정) — Access 가 관문 | `smtp` (메일 발송 확정 후) | 기관 메일 서버 기준 |
| `PORTAL_ACCESS_TEAM_DOMAIN` / `PORTAL_ACCESS_AUD` | 설정됨(터널) | 터널 안 쓰면 비움 | 비움 |
| `PORTAL_HARNESS_RELEASE_URL` | 기본(GitHub Pages) | GitHub 가능하면 기본, 아니면 깃랩 미러 URL | 내부 파일 서버 URL |

`PORTAL_EXPECTED_CHECKER_COMMIT` 은 어느 상황이든 **두는 것이 원칙**이다. 값이 다르면 포털이 `/health` 503 + 점검 거부(`configuration_error`)로 알린다. 값이 없으면 `unverified` 로만 남는다.

### 3-3. 방화벽 허용 목적지(서버 → 외부)

| 목적지 | 용도 | 필수 여부 |
|---|---|---|
| github.com (releases) | 인텔 번들 · 하네스 release-index | B 에서 필수, C/D 불필요 |
| gitlab.aigov.go.kr | 번들 미러 · 점검 대상 저장소 clone | C 에서 필수 |
| pypi.org · registry.npmjs.org | 패키지 실재·발행일(쿨다운) | 선택 — 없으면 "미확인 → 검토" 판정(안전 쪽) |
| osv.dev · services.nvd.nist.gov · knvd.krcert.or.kr | (없음) | **불필요** — 서버는 부르지 않는다 |

### 3-4. 상황별 추가 작업

| 상황 | 추가 작업 |
|---|---|
| A | (선택) NSSM 환경에 `GVSKB_CACHE_DIR` 지정 후 서비스 재시작 — 없으면 KEV·NVD·KNVD 병기가 빠진다 |
| B | 예약 작업 `pull-intel-bundle` 등록(다운로드·sha256·intel-sync), inbox·cache 폴더 권한(서비스 계정 읽기/쓰기) |
| C | B + GitHub Actions 깃랩 미러 단계, 깃랩 토큰 secret |
| D | 반입 절차서(외부망 PC 다운로드 → sha256 대조 → USB → inbox → `gvskb intel-sync` → `gvskb doctor --offline`) |
| 공통 | 번들 서명(Ed25519)·기관 공개키 배포는 서버 이전 조건 — docs/25 |

## 4. 확인 명령 (설정 후)

```powershell
# 포털이 어떤 체커를 쓰는지 · 예상 커밋과 일치하는지
Invoke-RestMethod http://127.0.0.1:8787/health | ConvertTo-Json -Depth 4
#   checker_identity.commit == 예상 커밋, identity_state == ok

# 서비스 계정 기준 인텔 캐시 상태(서비스와 같은 환경변수로 실행할 것)
gvskb doctor --offline
gvskb update-intel --all --from-cache        # 소스별 항목 수·수집 시각·stale 여부
```
