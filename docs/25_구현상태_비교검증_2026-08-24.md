## 5. 우선순위 제안

원칙: **(a) 서버가 죽지 않게 → (b) 데이터가 사라지지 않게 → (c) 남의 것이 보이지 않게 → (d) 목표 기능의 얼굴 → (e) 다듬기.**

| 순위 | 작업 | 이유 | 규모 |
|---|---|---|---|
| **P1** | **S2: 큐·동시상한·타임아웃·디스크 워터마크 + 대기열 화면(4)** | 몇 명만 동시에 눌러도 서버가 멎는 상태. 다중 사용자의 전제 | 소 |
| **P2** | **S3: DB 연결 + 관측 축적 파이프** | ⑤의 원료가 **매 검사마다 버려지는 중** — 파이프를 빨리 놓을수록 화이트리스트 근거가 그만큼 쌓임. 검사 완료 시 `dependency_audit.checks` → `package_observations`+`package_usage_stats` | 중 |
| **P3** | **S4: 인증 어댑터 + 소유자 검증 + 내 이력(6)** | 공개 배포의 차단 조건. 임시 어댑터로 착수, B3 확정 병행 | 중 |
| **P4** | **S5: 관리자 화이트리스트 3화면(후보·문제·상세) + 현황 보강** | ⑤의 얼굴. P2가 쌓아 둔 데이터를 보여 줌 | 중 |
| **P5** | 결과 화면 보강(원본삭제·보존기한·confidence) + 메인 3택 정리 + 보고서 보존기한 자동삭제 | 신뢰 표시와 정리. 기능 차단 요소는 아님 | 소 |
| P6 | S6 내보내기 4형식 / S7 서버 배포 / S8 도구 관리자 실행체 | 각각 망중계 규격·서버 자원·B2 확정 대기 | — |

**P1·P2는 외부 확정 사항 없이 지금 바로 가능하다.** P3부터 B3(기관 인증)가 실질 변수이나, 어댑터 구조로 임시 착수는 가능하다.

## 추기 (같은 날) — 사용자 요구 개정 반영

화면 확인 과정에서 요구가 구체화되어 설계에 반영했다(화면 개정판: `26_화면설계_개정_2026-08-24.html`, 문서: 22번 §4-4·§4-5·§5-4, 23번 §1-A·§2-6·§2-7·§4-9·§4-10).

1. **인증**: 일반 공무원은 기관 메일 가입 + 기관·부서 선택(도메인 제한, B3 확정 시 로그인 수단 교체하는 임시 경로). 관리자는 별도 계정으로 /admin 로그인.
2. **점검결과 제출(opt-in)**: 자동 축적이 아니라 결과 화면의 제출 버튼으로 메타값만 제출 → 화이트리스트 후보. **P2의 관측 축적 파이프는 "검사 시 자동"이 아니라 "제출 시 적재"로 구현 방향 변경.**
3. **보안성 검토 요청**: 신설 — 관리자 대기열 + 내 이력 상태 표시. P3~P4 범위에 편입.
4. **화이트리스트 관리**: 08-13 "내보내기만" 결정 갱신 — 관리자가 담기·제외·저장까지(감사 기록 필수). P4 범위 확대.

우선순위 순서(P1→P5)는 유지하되 P2·P3·P4의 내용이 위와 같이 조정된다.
