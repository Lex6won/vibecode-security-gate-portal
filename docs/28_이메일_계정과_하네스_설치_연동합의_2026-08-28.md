# 이메일 계정·하네스 설치·서버 체커 연동 합의

> 대상: `vibecode-security-gate-portal`, `vibecode-checker`, `vibecode-harness`
>
> 상태: 2026-08-28 제품 방향 합의. 기존 문서 중 로컬 체커 설치, 부서 협업 작업공간, 비밀번호 로그인 전제와 충돌하는 내용은 이 문서를 우선한다.

## 1. 역할 경계

| 구성요소 | 책임 | 하지 않는 일 |
|---|---|---|
| 포털 | 이메일 계정, 배포·업데이트 안내, 점검 요청·이력·보고서, 서버 체커 운영 | 개발 PC 파일 수정, AI 도구 로그인 정보 수집, 체커 판정의 임의 변경 |
| 체커 | 포털이 만든 점검 작업의 소스·의존성 분석, 원본 HTML/JSON 보고서 생성 | 사용자 계정·비밀번호 관리, 승인/차단의 행정 결정, 사용자 PC 설치 요구 |
| 하네스 | 개발 PC에서 프로젝트별 AI 도구 설정·훅·플러그인 적용, 백업·복구, 포털 점검 요청 | 체커를 사용자 PC에 설치, AI 도구 토큰 수집, 포털 계정 인증을 대체 |

협업 작업공간과 부서 공용 계정은 제공하지 않는다. 모든 점검 이력은 개인 이메일 계정에 연결한다.

## 2. 포털 계정

포털은 비밀번호를 사용하지 않는다. 최초 입력은 이메일, 기관명, 부서명이다.

```text
이메일 입력 → 일회용 이메일 인증/로그인 링크 → 링크 클릭 → 계정 생성 또는 로그인
```

- 인증 링크는 1회 사용, 10~15분 만료, 요청 횟수 제한과 봇 방어를 적용한다.
- 인증 뒤에는 현재 브라우저의 로그인 상태를 유지한다. 새 브라우저·새 기기·로그아웃 상태에서만 이메일 링크를 다시 사용한다.
- 어려운 인증 기술 용어를 사용자 첫 화면에 노출하지 않는다.
- 이메일은 인증, 로그인 링크, 개인 점검 이력 조회, 보안 안내를 위해 저장한다.
- 기관명·부서명은 현재 프로필로 저장하며 사용자가 수정할 수 있다. 이메일 변경은 기존·새 이메일을 모두 인증한다.
- 기관명·부서명 변경 이력과 보고서 생성 시점의 소속 스냅샷은 보존한다. 현재 프로필을 고쳐도 과거 보고서의 스냅샷은 바꾸지 않는다.
- 이메일 인증은 실제 기관·부서 소속 증명이 아니다. 기관명·부서명은 개인 프로필 표시에만 쓴다.

## 3. 서버 체커 점검

체커는 포털 서버에만 설치·업데이트한다. 사용자 PC에 `gvskb.exe`, Python 또는 체커 의존성을 설치하도록 요구하지 않는다.

소스 전송 규칙은 다음과 같다.

1. 하네스 상태 보고에는 프로젝트 소스, 로컬 경로, 프롬프트, 토큰, 쿠키, 비밀번호, 개인키, 환경변수를 넣지 않는다.
2. 서버 점검은 사용자가 명시적으로 요청할 때만 시작한다.
3. 요청 전 포털 또는 Harness Manager는 전송할 소스 범위와 원본·보고서 보관 정책을 보여 주고 동의를 받는다.
4. 체커 작업은 사용자 계정과 점검 작업 ID에 묶는다. 추측 가능한 ID만으로 보고서나 결과를 조회할 수 없어야 한다.
5. 업로드 원본은 작업별 격리 영역에서만 처리하고 성공·실패·취소와 무관하게 분석 종료 뒤 삭제한다. 보고서는 별도 보관 기간 정책을 적용한다.
6. 포털은 체커가 생성한 보고서를 임의 재작성하지 않으며, `점검 요청됨 → 분석 중 → 완료/검토 필요/실패` 상태만 전달한다.

체커는 포털에 최소한 아래 결과를 반환한다.

```text
scan_id, owner_account_id, status, checker_version,
report_html_reference, report_json_reference,
completed_at, retention_until, verdict/evidence completeness
```

`owner_account_id`는 내부 식별자이며 이메일 원문을 체커 로그·보고서에 복제하지 않는다.

## 4. Harness Manager 사용자 경험

공식 EXE 설치 뒤 Harness Manager를 연다. 설치 단계에서 도구를 고정 선택하지 않고, 프로젝트별로 선택한다.

```text
프로젝트 폴더 선택
  → 설치된 Codex·Claude Code·Google Antigravity 자동 감지
  → 감지된 도구를 기본 선택
  → [이 프로젝트에 적용]
```

사용자는 이후에도 해당 프로젝트의 도구를 바꿀 수 있어야 한다.

| 변경 | 하네스 동작 |
|---|---|
| 도구 추가 | 해당 도구의 지침·보조 파일·훅·플러그인 적용 |
| 도구 해제 | 하네스 소유 항목만 제거 또는 백업 |
| 기존 설정 발견 | 변경 전 백업, 안전한 병합, 충돌 시 수동 확인 |
| 변경 실패 | 이전 상태로 복구 |

Codex, Claude Code, Antigravity의 로그인은 각 도구의 기존 세션을 사용한다. 하네스와 포털은 해당 도구의 ID, 비밀번호, 토큰, 쿠키를 읽거나 전송하지 않는다.

## 5. 포털-하네스 상태 연동

사용자 동의 후 하네스가 보내는 상태는 최소화한다.

```json
{
  "manager_version": "x.y.z",
  "harness_version": "x.y.z",
  "os_family": "Windows",
  "installation_status": "healthy",
  "applied_tools": ["codex", "claude-code"],
  "doctor_summary": "ready",
  "reported_at": "UTC timestamp"
}
```

상태 전송에 프로젝트명·프로젝트 경로·소스·보고서 본문·AI 자격증명을 포함하지 않는다. 사용자는 포털에서 연결된 기기를 해제하고 계정을 삭제할 수 있어야 한다.

## 6. 구현 우선순위

### 포털

1. 이메일 링크 인증과 개인 계정
2. 이메일·기관명·부서명 프로필 조회·수정과 변경 이력
3. 점검 작업의 소유자 검증, 업로드 동의 화면, 원본 삭제·보고서 보관 정책
4. 개인 점검 이력과 보고서 접근 제어
5. 서명된 Harness Manager EXE 다운로드·업데이트 정보

### 체커

1. 포털 서버의 격리 작업 디렉터리에서만 실행
2. 작업 ID·소유자 ID·체커 버전·원본 보고서 참조를 반환
3. 작업 종료 후 원본 삭제를 호출 가능한 명확한 종료 경로 제공
4. 체커 결과를 승인으로 임의 승격하지 않고, 관측·보고 역할을 유지

### 하네스

1. 콘솔 `init --interactive` 대신 GUI 폴더·도구 선택
2. 프로젝트별 도구 추가·해제·복구(`configure`, `restore` 계층)
3. 사용자 EXE에서 로컬 체커·Python 의존성 제거
4. 이메일 인증을 마친 포털 계정과 안전하게 연결
5. 동의 기반 최소 상태 보고 및 명시적 서버 점검 요청

## 7. 완료 기준

- 사용자는 비밀번호 없이 이메일 인증만으로 포털을 쓸 수 있다.
- 이메일, 기관명, 부서명은 확인·수정 가능하고 과거 보고서의 당시 소속 정보는 보존된다.
- 체커는 서버에서만 실행되며 사용자 PC 체커 설치를 요구하지 않는다.
- 소스는 자동 전송되지 않으며 사용자가 점검을 명시적으로 요청한 범위만 처리한다.
- 사용자는 EXE 설치 뒤 프로젝트 폴더와 AI 도구만 선택해 적용하고, 나중에 도구 선택을 변경할 수 있다.
- 포털·하네스는 AI 자격증명과 불필요한 로컬 정보를 수집하지 않는다.
