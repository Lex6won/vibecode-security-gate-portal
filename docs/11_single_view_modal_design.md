# 단일 화면·레이어 UX 설계

## 원칙

모든 핵심 화면은 스크롤 없이 한 화면에서 끝낸다.

공무원 사용자는 화면을 읽으며 탐색하는 것이 아니라, 지금 해야 할 일을 바로 선택해야 한다. 따라서 본문 화면에는 핵심 입력과 주요 버튼만 남기고, 설명·진행·확인·오류는 레이어 팝업으로 분리한다.

## 화면 구조

기본 화면은 4개 영역으로 고정한다.

| 영역 | 역할 | 높이 기준 |
|---|---|---:|
| 헤더 | 서비스명, 홈, 도움말, GitHub 링크 | 64~76px |
| 핵심 설명 | 이 화면에서 할 일 한 문장 | 96~140px |
| 작업 영역 | 선택, 입력, 실행 버튼 | 남은 높이의 대부분 |
| 상태 요약 | 결과 또는 현재 상태 3~5개 | 우측 또는 하단 고정 |

본문에서 세로 스크롤이 필요해지면 정보를 덜어낸다. 덜어낸 정보는 도움말, 상세보기, 진행상황 레이어로 보낸다.

## 레이어 팝업 종류

### 진행상황 레이어

검사 시작, 상태 점검, MCP 등록, 업데이트 적용 중에만 표시한다.

표시 항목:

- 현재 단계
- 진행률
- 실행 중인 작업명
- 중단 버튼
- 로그 보기 버튼

닫기 정책:

- 실행 중에는 `숨기기`만 가능
- 실패 또는 완료 후에는 `닫기` 가능
- 실패 시 본문 상태 요약도 함께 갱신

### 변경 내용 미리보기 레이어

구버전이 확인됐을 때 표시한다.

표시 항목:

- 현재 버전
- 최신 안정 버전
- 출처
- 변경 요약
- 검증 상태
- 설정 백업 예정 여부
- 적용 후 재검증 항목

이 레이어에서는 설치하지 않는다. `업데이트 적용 준비`를 누르면 승인 레이어로 넘어간다.

### 승인 레이어

설치, 업데이트, MCP 설정 변경처럼 PC 상태를 바꾸는 작업 전에 표시한다.

표시 항목:

- 바뀌는 파일
- 백업 위치
- 실행 명령 요약
- 실패 시 조치

승인 문구:

```text
변경 내용을 확인했습니다.
```

사용자가 승인하지 않으면 작업을 실행하지 않는다.

### 결과 레이어

검사 완료 후 상세 결과를 보여준다.

표시 항목:

- 제출 가능 여부
- 수정 필요
- 사람 검토 필요
- 의존성 취약점
- 보고서 저장 결과

본문에는 요약만 남기고, 상세 목록은 이 레이어 또는 별도 상세 화면에서 본다.

### 오류 레이어

실패 원인과 다음 조치만 보여준다.

예시:

- 검사할 파일을 찾지 못했습니다.
- GitHub 저장소를 가져오지 못했습니다.
- 체커 실행이 끝나지 않았습니다.
- 보고서를 저장하지 못했습니다.
- MCP 설정 파일을 바꾸지 못했습니다.

오류 레이어에는 `다시 시도`, `도움말 보기`, `로그 보기`만 둔다.

## 화면별 적용

### 홈

한 화면에 남길 것:

- 서비스명
- 한 줄 설명
- 표준 점검 시작
- 빠른 점검
- 하네스 및 MCP 등록
- 관리자 로그인

레이어로 보낼 것:

- 자세한 서비스 설명
- GitHub 소개
- 도움말

### 보안 점검

한 화면에 남길 것:

- 검사 대상 선택
- 검사 방식 선택
- 저장 위치 선택
- 점검 후 확인 요약

레이어로 보낼 것:

- 검사 진행상황
- 검사 로그
- 결과 상세
- 오류 안내

### 하네스 및 MCP 등록

한 화면에 남길 것:

- 내 PC 상태 카드
- 상태 점검 시작
- 업데이트 확인
- 설치 대상 선택
- 선택한 하네스 설치
- MCP 등록 시작

레이어로 보낼 것:

- 구버전 업데이트 상세
- 변경 내용 미리보기
- 설치 승인
- MCP 설정 변경 목록
- 진행상황
- 연결 검증 결과

### 관리자

한 화면에 남길 것:

- 기간 필터
- 검사 결과 요약
- 최근 검사 목록
- 선택 검사 요약

레이어로 보낼 것:

- 검사 상세
- 룰별 반복 발생 상세
- 오탐 후보 상세
- 감사 로그

## 금지

- 진행상황을 본문 아래에 추가해 화면을 밀어내기
- 한 화면에 설명 카드와 결과 카드와 상세 표를 모두 배치하기
- 긴 텍스트로 기능을 설명하기
- 버튼 클릭 후 사용자가 아래로 스크롤해야 결과를 찾게 만들기
- 업데이트 확인과 업데이트 적용을 같은 버튼으로 합치기

## 구현 기준

- 기본 viewport 기준은 `1280 x 720`과 `1440 x 900`을 모두 확인한다.
- 본문 루트는 `height: 100vh`, `overflow: hidden`을 기준으로 한다.
- 레이어 내부 내용이 길면 레이어 안에서만 스크롤한다.
- 모바일에서는 한 화면 원칙을 유지하되, 카드 수를 줄이고 단계별 레이어를 우선한다.
- 모든 레이어는 `Escape` 닫기, 포커스 이동, 명확한 닫기 버튼을 제공한다.
