# 33. 디자인 변경 지시서 (코덱스용)

> 대상: 업무PC에서 화면 디자인을 수정하는 코덱스.
> 이 저장소는 **개발 클론 → GitHub → (노트북의 클로드코드가) 태그 배포** 순서로 흐른다.
> **코덱스의 역할은 "수정 → 검증 → main 푸시"까지다. 태그 생성·배포·서버 접근은 하지 않는다.**

---

## 1. 시작 전 (항상)

```bash
git pull --ff-only
```

다른 PC에서 작업이 이어지고 있으므로, 풀 없이 시작하면 충돌이 난다.
충돌·경고가 나오면 멈추고 사용자에게 보고한다.

## 2. 어디를 수정하는가

화면은 전부 **`design/html-prototype/`** 아래의 정적 파일이다. 빌드 단계가 없다 — 파일을 고치면 그게 곧 배포물이다.

| URL | 파일 |
|---|---|
| `/` | `design/html-prototype/main page.html` (파일명에 공백 있음, 그대로 유지) |
| `/scan` | `design/html-prototype/security-scan.html` |
| `/tools`, `/harness` | `design/html-prototype/tools.html` |
| `/my` | `design/html-prototype/my-scans.html` |
| `/help` | `design/html-prototype/help.html` |
| `/admin`, `/admin/login` | `design/html-prototype/admin.html`, `admin-login.html` |
| 공통 스타일 | `design/html-prototype/shared.css` (`/shared.css` 로 서빙) |

각 페이지는 자체 `<style>` + `shared.css` 조합이다. 공통으로 바꿀 건 shared.css, 페이지 고유는 해당 파일의 `<style>` 에서 고친다.

## 3. 수정 금지 구역

- **`src/server.js`** — 판정·검사·인증 로직. 디자인 변경으로 건드릴 일 없음.
- **`scripts/`** — 테스트. 단, §5의 "의도된 문구 변경" 경우에만 같은 커밋에서 함께 수정.
- **`.env`, 비밀값** — 어떤 파일로도 커밋 금지. 주소·토큰·비밀번호를 HTML에 하드코딩하지 않는다.
- **`C:\servers\` (운영 서버 폴더)** — 접근 금지. 배포는 노트북의 클로드코드만 한다.

## 4. 지켜야 할 화면 규약

1. **숨김 처리는 `hidden` 속성으로만.** `shared.css` 에 `[hidden]{display:none!important}` 전역 규칙이 있다. `style.display` 직접 조작이나 이 규칙 삭제 금지 (class의 `display:flex` 가 hidden을 이기는 버그를 이 규칙으로 잡았다).
2. **단계 진행 표시**: `/scan` 은 `data-step-state="active|done|pending"` 로 현재 단계를 색으로 구분한다. 단계 박스를 재배치해도 `stepSections`/`markStep`/`updateStepStates` 연결을 끊지 않는다.
3. **결과 숫자는 정직하게.** 화면 요약은 다운로드 보고서와 같은 숫자를 말해야 한다. "못 본 것"을 "0건"으로 표기하는 문구·구조로 되돌리지 않는다 (경고는 경고대로, 의존성 미확인은 "확인 불충분"으로).
4. **문구는 사용자가 반드시 알아야 할 것만.** "~할 필요가 없다" 류의 설명, 중복 안내, 긴 배경 설명은 넣지 않는다. 상세 설명은 `<details>` 로 접는다.
5. 외부 링크는 `target="_blank" rel="noreferrer"` 필수, `href="#"` 금지, 버튼은 반드시 스크립트에 연결(id 참조)되어야 한다 — 테스트가 자동으로 검사한다.

## 5. 검증 (푸시 전 필수)

```bash
npm run check          # 문법 + 폴더픽커 계약
npm run button:test    # 버튼·링크·문구 계약 (서버 자동 기동)
npm run scenario:test  # 15개 시나리오 (약 1~2분)
```

gvskb(체커 CLI)가 설치된 PC면 전체 묶음 `npm run guard` 를 대신 실행한다 (2~4분, 끝나면 `reports/` 폴더 삭제 — 자기점검 산출물이라 커밋 금지).

**주의**: `portal-button-contract-test.mjs` 와 `portal-scenario-test.mjs` 는 특정 문구·id를 **문자 그대로** 검사한다 (예: `점검결과를 저장할 위치를 선택해 주세요.`, `id="saveLocationPrompt"`, 보고서 파일명 `_간편점검/_표준점검`). 디자인 변경으로 이런 문구·id를 **의도적으로** 바꾸는 경우에만, 같은 커밋에서 해당 assert 도 함께 고친다. 테스트를 지우거나 건너뛰어서 통과시키는 것은 금지.

눈 검증: `npm start` 로 로컬 기동 후 브라우저에서 실제 확인. 헤드리스 스크린샷도 가능:

```
"C:/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu --window-size=1280,900 --virtual-time-budget=4000 --screenshot=out.png http://127.0.0.1:8787/scan
```

(포트는 로컬 `.env` 의 `PORT` 값. 데스크톱 폭 1280과 모바일 폭 420 두 가지로 찍어 깨짐을 확인한다.)

## 6. 커밋·푸시

```bash
git add design/ [필요시 scripts/]
git commit -m "fix(ui): <무엇을 왜 바꿨는지 한 줄, 한국어>"
git push
```

- 커밋은 화면 변경 단위로 작게. `reports/`, `.env`, 스크린샷 파일은 커밋하지 않는다.
- 푸시가 끝나면 사용자에게 **"어느 파일의 어느 화면을 바꿨는지"** 보고한다. 이후 배포(태그 → 서버 반영)는 노트북의 클로드코드가 `docs/31` 절차로 진행한다.
