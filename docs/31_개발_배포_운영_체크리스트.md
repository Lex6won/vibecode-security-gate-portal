# 개발·배포·운영 체크리스트 (2026-08-29)

> **이 문서의 용도**: 개발 PC 가 둘(업무 PC·집 노트북)이고 서버가 하나인 상태에서
> 무엇을 어디서 하고, 다른 PC 로 옮길 때 무엇을 먼저 하는지를 못 박는다.
> 서비스가 안정될 때까지 작업 시작 전에 이 문서를 편다.
>
> 절차의 정본은 `docs/29_서버_구축_절차서.md` — 서버 구축·배포 명령의 상세는 29 번이 우선.

## 0. 지금의 구조 (세 자리)

| 자리 | 경로 | 역할 | git |
|---|---|---|---|
| 업무 PC 개발클론 | (업무 PC) | 코드·화면 수정 | `main` 에서 작업·push |
| 집 노트북 개발클론 | `C:\coding\vibecode-security-gate-portal` (포트 8788) | 코드·화면 수정 | `main` 에서 작업·push |
| **집 노트북 서버** | `C:\servers\vibecode-security-gate-portal` (포트 8787) | 상시 가동 서비스 | **태그만 체크아웃. 편집·커밋 금지** |

```
[업무 PC 개발클론]  ─┐
                     ├→ git push (main) → [GitHub] → 태그 push
[집 노트북 개발클론] ─┘                        │
                                               ↓  서버에서 명시적으로 실행
                              [서버]  .\scripts\deploy-server.ps1 -Tag v0.4.0
```

- **push 는 배포가 아니다.** 서버는 자동으로 바뀌지 않는다 — 배포 명령을 실행해야 반영된다.
- 배포는 `main` pull 이 아니라 **태그 체크아웃**이다. 롤백이 같은 명령 한 줄로 되기 때문(`-Tag <이전 태그>`).
- 배포가 건드리는 것은 **git 이 추적하는 코드뿐**이다. `.env`(gitignore)와 `C:\portal-data\`(코드 폴더 밖)는 그대로 남는다.

## 0-1. 개발클론 세팅 (새 PC 에서 처음 한 번)

운영 서비스와 **포트·데이터를 반드시 분리**한다. 같은 기계에 서버와 개발클론이 함께
있으면(집 노트북) 분리하지 않을 때 개발 중 시험 점검이 **운영 관측 원장·이력을 오염**시킨다.
관측은 경기도 화이트리스트의 근거이므로 오염되면 사업 목적 자체가 훼손된다.

```powershell
cd C:\coding                      # 서버 폴더(C:\servers)와 다른 곳에
git clone https://github.com/Lex6won/vibecode-security-gate-portal
cd vibecode-security-gate-portal
npm ci
git config core.hooksPath .githooks    # 새 클론은 pre-commit 이 안 걸려 있다 — 반드시 설정
```

> `core.hooksPath` 를 빼먹으면 `npm run guard` 가 커밋 때 자동으로 돌지 않는다.
> 집 서버 구축 때 실제로 겪은 함정이다.

개발용 `.env` (저장소 루트, git 미추적):

```ini
PORT=8788
# PORTAL_BIND_HOST 미설정 = 127.0.0.1 전용 (개발 서버는 외부에 열지 않는다)
PORTAL_ALLOWED_EMAIL_DOMAINS=gg.go.kr,korea.kr
ADMIN_ID=<관리자 이메일>
ADMIN_INITIAL_PASSWORD=<운영과 동일하게 관리할 관리자 비밀번호>
# 개발·운영의 같은 관리자 계정을 유지할 때만 활성화
ADMIN_CREDENTIALS_SYNC=true

# 데이터는 운영(C:\portal-data)과 반드시 분리
PORTAL_ACCOUNT_DIR=C:\portal-data-dev\accounts
PORTAL_SCAN_HISTORY_FILE=C:\portal-data-dev\scan-history.jsonl
PORTAL_OBSERVATION_DIR=C:\portal-data-dev\observations
PORTAL_WHITELIST_DIR=C:\portal-data-dev\whitelist
PORTAL_REPORT_DIR=C:\portal-data-dev\reports
ADMIN_AUTH_FILE=C:\portal-data-dev\admin-auth.json
```

실행·확인:

```powershell
npm start                                   # http://127.0.0.1:8788 (Ctrl+C 로 종료)
Invoke-RestMethod http://127.0.0.1:8788/health
```

집 노트북에서는 개발(8788)과 운영(8787)이 **동시에** 돌아간다 — 실측 확인함.
포트나 데이터 경로가 겹치면 둘 중 하나가 뜨지 않거나 운영 데이터가 섞이므로 위 값을 지킨다.

관리자 계정은 두 환경의 `.env`에 같은 `ADMIN_ID`와 `ADMIN_INITIAL_PASSWORD`를 넣고 `ADMIN_CREDENTIALS_SYNC=true`로 동기화한다. 데이터 경로는 계속 분리하며, 운영 `.env` 변경과 재시작은 별도 배포 절차에서만 수행한다.

체커(`gvskb`)는 기계에 하나만 설치돼 있으면 개발·운영이 같이 쓴다(읽기 전용 도구라 문제 없음).
집 노트북 기준 `C:\servers\checker-venv\Scripts` 가 Machine PATH 에 있다 — `docs/29 §2` 참고.

## 1. 다른 PC 에서 작업을 **시작하기 전** (필수)

개발 PC 가 둘이므로, 자리를 옮기면 **반드시** 이 순서로 시작한다.

```powershell
cd <개발클론 경로>

git status                    # ① 지난번 작업이 커밋 안 된 채 남아 있지 않은지
git pull --ff-only origin main   # ② 다른 PC 가 올린 것을 먼저 받는다
git fetch --tags                 # ③ 서버에 배포된 태그 목록 동기화
git log --oneline -3             # ④ 마지막 커밋이 다른 PC 에서 올린 그것인지 눈으로 확인
```

- **② 가 실패하면(`--ff-only` 거부)** = 양쪽에서 갈라졌다는 뜻. 그냥 merge 하지 말고 무엇이 갈라졌는지 먼저 본다: `git log --oneline --graph --all -10`.
- **package-lock.json 이 바뀌었으면** 의존성도 맞춘다:
  ```powershell
  git diff HEAD@{1} --name-only | Select-String package-lock
  npm ci      # 위에서 걸리면 실행
  ```
- 서버가 지금 무엇을 돌리고 있는지 확인: `git tag --list --sort=-v:refname | Select-Object -First 5`

## 2. 자리를 **뜨기 전** (필수)

**가장 흔한 사고가 "push 안 하고 자리를 뜨는 것"이다.** 다음 PC 에서 작업을 이어갈 수 없고,
모르고 작업하면 갈라진다.

```powershell
git status                  # 남은 변경 없는지
git add -A
git commit -m "wip: <무엇을 하다 말았는지>"   # 미완이어도 커밋한다
git push origin main
```

- 완성된 작업이면 §3 으로, 미완이면 `wip:` 커밋으로라도 **반드시 push**.
- 서버 폴더(`C:\servers\...`)에서는 아무것도 커밋하지 않는다.

## 3. 배포할 때 (개발클론 → 서버)

개발클론에서:

```powershell
npm run guard               # 2~4분. 통과해야 배포 자격 (pre-commit 이 자동으로 돌린다)
git push origin main
git tag v0.4.0              # 첫 배포 태그는 v0.1.0 (package.json 기준)
git push origin v0.4.0
```

서버(`C:\servers\vibecode-security-gate-portal`, 관리자 권한)에서:

```powershell
.\scripts\deploy-server.ps1 -Tag v0.4.0
```

이 스크립트가 태그 받기 → 체크아웃 → `npm ci` → 문법·버튼 계약 검증 → 서비스 재시작 →
health 확인까지 한다. **검증에 실패하면 재시작 없이 중단**한다.

- 배포 후 서버는 detached HEAD 가 된다 — 정상이다.
- **롤백**: 같은 명령에 이전 태그. `.\scripts\deploy-server.ps1 -Tag v0.3.0`

## 4. 화면(UI/UX)을 고칠 때

- 화면은 정적 HTML 이다: `design/html-prototype/` 의 `main page.html`, `security-scan.html`,
  `my-scans.html`, `tools.html`, `help.html`, `admin.html`, `admin-login.html`, `shared.css`.
  라우트 매핑은 `src/server.js` 의 `staticRoutes`.
- 개발클론에서는 **서버 재시작 없이 브라우저 새로고침만으로** 반영된다
  (`serveStatic` 이 요청마다 파일을 읽고 `Cache-Control: no-store`).
- **화면을 바꾸면 `npm run button:test`(버튼 계약)와 `scenario:test` 가 깨질 수 있다.**
  페이지별 링크·버튼을 계약으로 고정해 둔 의도된 안전장치이므로, 계약도 함께 갱신해야 guard 가 통과한다.

## 5. 서버 운영 — 접속 주소가 바뀔 때

IP 는 ①공유기 재부팅 ②DHCP 임대 만료 ③다른 망 접속 에서 바뀐다. 바뀌면
`.env` 의 `PORTAL_ALLOWED_HOSTS` 와 안 맞아 **421 로 거부**된다.

- **근본 해결**: 공유기에서 이 노트북 MAC 에 **DHCP 예약**을 걸어 IP 를 고정한다.
- **바뀐 뒤 복구**: 관리자 권한 PowerShell 에서 `& 'C:\servers\refresh-address.ps1'`
  (IP 재탐지 → `.env` 갱신 → 망 프로파일 Private 확인 → 서비스 재시작 → health)
- 새 와이파이에 처음 붙으면 윈도우가 프로파일을 **Public 으로 잡는다**. 방화벽 규칙이
  Private 한정이라 그대로 두면 다른 기기에서 막힌다 — 위 스크립트가 함께 처리한다.

## 6. 하지 말 것

- 서버 폴더에서 **코드 편집·커밋 금지**. 로컬 수정이 있으면 `git checkout --detach` 가 거부돼
  **다음 배포 자체가 깨진다**.
- 서버에서 `main` pull 금지. 태그 배포만.
- 인터넷 직접 공개(포트포워딩·DDNS) 금지. 외부 접속은 `docs/29 부록 A-1`(Cloudflare Tunnel + Access) 로만.
- 판정·검사 로직 완화 금지 — 역할 경계는 `docs/27` (체커=관측, 하네스=집행, 포털=편의, 판정=보안부서).

## 7. 현재 열려 있는 항목

- **인증이 개발 모드**(`PORTAL_AUTH_MODE` 미설정): 로그인 링크가 화면에 그대로 뜬다.
  같은 와이파이에 있는 사람이면 `@gg.go.kr` 아무 주소로나 세션을 받을 수 있다.
  SMTP 확정 전까지 **테스트 데이터 전용**이며, 실업무 소스를 올리지 않는다.
  방화벽 규칙의 허용 원격주소가 `Any` 이므로, 필요하면 기기 IP 단위로 좁힌다.
- 통신이 HTTP 평문이다 — 같은 망에서 업로드 소스·세션 쿠키가 노출될 수 있다.
- 관리자 초기 비밀번호는 `.env` 에만 있다. 첫 로그인 후 변경한다.
