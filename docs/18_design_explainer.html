무엇을 누가 3단계 코드 보호 배포 경로 안전한 이유 보안팀 로드맵
2026-08-10 설계 확정본

공무원이 AI로 만든 코드를
안전하게 점검하는 도구

검사는 사용자 PC 안에서만 돌고, 경기도 서버는 안내와 배포·통계만 맡습니다. 코드는 어디로도 올라가지 않습니다.

0건서버로 올라가는 소스 코드
설치 없이개발 기준·규칙 열람과 체험
분기 1회보안팀이 해야 하는 일
1

무엇을 만드나

역할이 완전히 다른 두 개를 만듭니다. 하나로 합치면 안전하지 않거나 쓸 수 없게 됩니다.

① 경기도 내부 서버 웹 포털

브라우저로 들어가는 안내 창구

  • 개발 기준(하네스) 열람·내려받기
  • 체커가 무엇을 검사하는지 규칙 목록
  • 설치 파일 배포와 최신 버전 안내
  • 관리자 통계와 승인 화면
절대 하지 않는 것 — 코드를 받아서 서버에서 검사하지 않습니다.

② Windows 로컬 보안 에이전트

사용자 PC에 한 번 설치하는 프로그램

  • 폴더·압축파일을 실제로 검사
  • 보고서를 원하는 폴더에 저장
  • 체커·하네스 설치와 업데이트
  • AI 도구에 체커 연결(MCP)
Python이 없어도 됩니다 — 실행 환경이 프로그램 안에 들어 있습니다.
왜 나눴나? 브라우저는 보안 때문에 PC의 폴더를 마음대로 읽거나 프로그램을 실행할 수 없습니다. 반대로 서버가 코드를 받아 검사하면 "소스를 밖으로 내보내지 않는다"는 약속이 깨집니다. 그래서 안내는 웹이, 검사는 PC가 맡습니다.
2

누가 무엇을 하나

본인에게 해당하는 것만 보세요.

브라우저를 열고 필요한 것만 하면 됩니다

1
개발 기준 받기
설치 필요 없음

웹에서 압축파일을 받아 프로젝트 폴더에 풀면 끝입니다.

2
내 코드 점검하기
보안 에이전트 1회 설치

폴더를 고르고 버튼을 누르면 검사하고 보고서를 만들어 줍니다. 그대로 인쇄하면 결재 문서가 됩니다.

3
AI 도구에 연결하기
AI 도구를 쓰는 경우에만

코딩하는 도중에 AI가 자동으로 위험을 알려줍니다. AI 도구가 없으면 이 단계는 건너뛰어도 됩니다.

알아야 할 것 — Python·Node.js·Git을 따로 깔 필요가 없고, 터미널을 열 일도 없습니다.

개발 방식은 지금과 똑같습니다

인터넷망 PC에서 AI 도구를 쓰며 GitHub에 계속 push합니다. 달라지는 건 "배포"뿐입니다.

구간어디서AI 도구하는 일
개발인터넷망 개발 PC자유롭게 사용코딩·테스트·GitHub push
릴리스CI + 개발 PC사용 안 함gg-release 1.2.0 명령 1회
운영행정망 내부 서버무관승인·배포 (개발자 관여 없음)
새로 늘어나는 일 — 명령 하나 실행, 자동 생성된 변경 요약 한 줄 확인, 하드웨어 키 터치. 이게 전부입니다.
지켜야 할 원칙 — 행정망에서는 코드를 고치지 않습니다. 급한 수정도 인터넷망에서 하고 긴급 채널로 보냅니다. 안 그러면 소스가 두 갈래로 갈라집니다.

개별 릴리스가 아니라 규칙을 승인합니다

매번 눌러야 하는 승인 버튼은 결국 읽지 않고 눌립니다. 그래서 부담을 줄이는 것이 곧 통제를 지키는 방법입니다.

하는 일빈도내용
정책 승인분기 1회"어떤 조건이면 자동 승인해도 되는가"를 정하고 서명
이상 알림 대응연 몇 회의존성 추가·취약점 발견·자동 회수 발생 시에만
사후 감사분기 1회자동 승인 이력이 정책대로 적용됐는지 열람
사고 대응발생 시번들 회수(revoke)
평소에는 알림이 오지 않습니다. "승인해 주세요"를 반복하지 않고, 이상 신호가 있을 때만 연락합니다.
3

설치하지 않아도 쓸 수 있습니다

설치를 첫 관문으로 두면 대부분 거기서 멈춥니다. 아래 단계는 위 단계 없이 독립적으로 쓸 수 있습니다.

T0

설치 없음 · 브라우저만

필요한 것: 없음
  • 개발 기준(하네스) 받기 — 그냥 파일이라 압축만 풀면 적용됩니다
  • 체커가 무엇을 검사하는지 규칙 목록 보기
  • 샘플 보고서로 결과물 미리 확인
  • 맛보기 점검 — 브라우저 안에서만 돌고 코드가 전송되지 않습니다
제출용 보고서는 발급되지 않습니다. 참고용입니다.
T1

보안 에이전트 설치

필요한 것: 설치 파일 1회 실행 (40MB부터)
  • 폴더·압축파일 정식 점검
  • HTML·JSON·Markdown 보고서 발급 → 제출 판단에 사용 가능
  • 체커·하네스 설치와 업데이트
  • 터미널을 쓰는 사람을 위한 명령어 모드도 함께 제공
T2

AI 도구 연동 (선택)

필요한 것: Codex · Claude Code · Claude Desktop 중 사용 중인 것
  • 코딩하는 도중에 AI가 체커를 자동 호출
  • AI 도구가 없으면 이 단계는 아예 필요 없습니다. T0·T1만으로 서비스가 완결됩니다
할 수 있는 일아무것도 없음에이전트만에이전트+AI도구
개발 기준 받아서 적용●●●
규칙·샘플 보고서 열람●●●
맛보기 점검●●●
정식 점검 + 제출용 보고서○●●
코딩 중 AI 자동 점검○○●
4

코드는 PC를 떠나지 않습니다

서비스의 존재 이유입니다. 이 약속이 깨지면 공공기관 도입 명분이 사라집니다.

데이터사용자 PC경기도 서버
원본 소스·압축파일검사 중 임시 보관 후 삭제전송·저장 금지
보고서 본문사용자가 고른 폴더에 저장전송·저장 금지
전체 파일 경로화면에만 표시전송·저장 금지
검사 결과 요약(건수·규칙 ID)로컬 이력동의한 경우에만 익명으로
담당자·부서명수집 안 함수집 안 함
맛보기 점검은 어떻게 안전한가?
그 페이지는 브라우저가 네트워크 전송 자체를 차단하도록 설정해 제공합니다. "우리를 믿어 달라"가 아니라 기술적으로 보낼 수 없는 상태입니다.
솔직히 밝히는 예외
인터넷망에서 취약점 정보를 조회할 때는 패키지 이름과 버전이 외부로 나갑니다. 행정망에서는 이 조회 자체가 없습니다. 화면에도 안내합니다.
5

새 버전이 사용자에게 도달하는 길

단계를 눌러 자세히 보세요. GitHub에 올린 코드가 곧바로 사용자 PC로 가지 않습니다.

핵심 — GitHub과 사용자 PC 사이에 서명 검증이 두 번, 승인이 두 번 있습니다. 서버가 GitHub을 직접 바라보고 최신을 당겨오는 구조가 아닙니다.
6

왜 안전한가 — 직접 공격해 보세요

공격 상황을 골라 보세요. 어디서 막히는지 보여줍니다. 막지 못하는 구간도 솔직히 표시합니다.

🔑 개발자 릴리스 키

개발 PC의 하드웨어 키. "내가 만든 게 맞다"를 증명합니다. 사용자 PC는 이 키를 신뢰하지 않습니다.

🏛️ 경기도 배포 키

행정망 안에만 존재합니다. "경기도가 배포를 허가했다"는 뜻이고, 사용자 PC가 신뢰하는 유일한 키입니다.

🚫 CI에는 키가 없습니다

빌드 서버가 뚫려도 서명을 만들 수 없습니다. 키를 CI에 두면 나머지 방어가 전부 무의미해집니다.

7

보안팀 부담을 이렇게 줄였습니다

부담이 큰 절차는 반드시 형식화됩니다. 줄이는 것이 곧 통제를 지키는 방법입니다.

그냥 만들었다면

릴리스마다 승인
월 4~8회

망연계 신청 승인 + 배포 승인 이중. 결국 읽지 않고 누르게 됩니다.

이번 설계

정책만 승인
분기 1회

규칙을 한 번 정하면 그 안의 릴리스는 자동 처리됩니다. 벗어난 것만 올라옵니다.

무엇을 자동으로 하고, 무엇을 사람이 보나

기준은 "어떤 컴포넌트냐"가 아니라 "변경의 방향"입니다.

✅ 자동 승인 — 검사를 강화하는 변경

잘못되어도 오탐이 늘 뿐입니다. 불편하지만 안전합니다.

  • 취약점 정보 갱신
  • 규칙 추가만 있는 경우
  • 체커 자잘한 수정 + 새 패키지 0건

👤 사람 승인 — 검사를 완화하는 변경

잘못되면 위험이 그대로 통과합니다.

  • 규칙 삭제·심각도 하향·예외 추가
  • 새 패키지가 추가된 경우
  • 개발 기준(하네스) 변경
  • 에이전트 본체 새 버전

자동 승인이 위험하지 않은 이유

🐤 일부에만 먼저

자동 승인된 것은 소수 PC에 먼저 배포하고, 문제가 없을 때 전체로 넓힙니다.

⏪ 자동 회수

실패율이 높으면 사람을 기다리지 않고 즉시 되돌립니다.

🔍 사후 감사

자동 승인 건도 어떤 정책으로 통과했는지 기록이 남아 분기마다 확인할 수 있습니다.

양보하지 않은 것 — 개발자가 자기 릴리스를 스스로 승인하는 경로는 어떤 경우에도 만들지 않습니다. 한 번 열린 우회로는 상시 사용됩니다.

9

지금 정해야 할 3가지

설계 선택이 아니라 전제입니다. 정해지기 전에 해당 단계를 시작하면 다시 만들게 됩니다.

① 망연계 반입 규격

어떤 파일 형식·크기까지 들어올 수 있는지, 반복 반입으로 등록할 수 있는지. 압축파일이나 실행파일이 검역에서 막히면 형식을 협의해야 합니다.

확인처 — 정보보안담당관 · 망연계 운영부서
② Windows 코드서명 인증서

GPKI 기관 인증서로는 프로그램 서명이 되지 않습니다(용도가 다릅니다). 상용 인증서를 따로 확보해야 하며, 없으면 설치할 때 경고창이 뜹니다.

확인처 — 정보보안담당관 · 계약부서
③ 관리자 인증 연계

행정망은 인증을 직접 구현하는 것이 금지되어 있습니다. 기관 SSO나 Keycloak 같은 기존 인증에 연결해야 합니다.
