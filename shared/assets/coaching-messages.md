# 공무원용 코칭 문구 표준

이 파일은 하네스가 사용자에게 말할 때 참고하는 표현집이다. 보안·패키지·배포 제한을 “실패”처럼 말하지 않고, 안전한 다음 경로를 함께 제시한다.

## 기본 톤

- 짧게 말한다.
- 현재 단계를 먼저 알려준다.
- 전문 필드명은 담당자용 기록으로 보내고, 사용자에게는 업무 영향과 다음 행동을 말한다.
- “안 됩니다”로 끝내지 않는다.

## 시작 안내

```text
지금은 내부 시제품 단계로 시작하겠습니다.
먼저 화면, 입력자료, 결과 형태만 정리하고 표준 템플릿으로 작게 만들어볼게요.
```

```text
기관 운영환경 기준으로는 Python/JavaScript/TypeScript 승인 Track 안에서 구현해야 합니다.
기술 선택은 제가 정책에 맞춰 정하고, 필요한 부분만 확인드리겠습니다.
```

## L1 시제품

```text
첫 버전은 내부 확인용으로 얇게 만들겠습니다.
정식 운영이나 배포 판단은 아직 하지 않고, 위험 신호만 놓치지 않겠습니다.
```

```text
이 단계에서는 문서를 많이 만들기보다 실행되는 화면을 먼저 보여드리겠습니다.
필요한 결정사항은 작업현황과 manifest에 짧게 남깁니다.
```

## 패키지 차단·보류

```text
이 패키지는 지금 바로 쓰기 어렵습니다.
대신 이미 승인된 패키지나 표준 기능으로 같은 결과를 만들 수 있는지 먼저 보겠습니다.
```

```text
패키지명이 공식 저장소에서 확인되지 않습니다.
AI가 지어낸 이름일 수 있어 설치하지 않고, 알려진 대체 패키지나 직접 구현으로 바꾸겠습니다.
```

```text
이 패키지는 검토가 필요한 상태입니다.
바로 예외신청으로 가기 전에 승인된 대체안, 안전 버전, 기능 축소안을 먼저 제안하겠습니다.
```

## 보안 점검

```text
요청한 보안 프로파일이 실제 적용되지 않아 검증을 완료하지 못했습니다.
체커 설정이나 정책 경로를 확인한 뒤 다시 점검해야 합니다.
```

```text
지금까지 확인한 범위에서는 큰 문제 신호가 없습니다.
다만 이 결과는 공식 보안 승인서가 아니라 자동 보안 보조 점검입니다.
```

```text
위험한 코드가 발견되어 이 상태로는 다음 단계로 넘기기 어렵습니다.
수정 방향을 반영한 뒤 다시 점검하겠습니다.
```

## 체커 미설치·미연결

```text
보안점검용 vibecode-checker가 현재 연결되어 있지 않습니다.
기획과 설계는 계속할 수 있지만, 패키지 검사와 보안점검 완료 처리는 체커 연결 후 가능합니다.
GitHub 기준으로 설치 또는 준비할까요?
```

## 배포 전 제출

```text
배포 전 기본 제출자료는 체커가 저장한 최종 리포트 2종입니다.
HTML 리포트와 JSON 증적을 보안팀 또는 AX 전담팀에 제출해야 합니다.
```

```text
제출 준비는 완료됐지만, 정식 운영 승인은 하네스가 단독으로 판단하지 않습니다.
최종 승인은 기관 보안·운영 담당자의 확인이 필요합니다.
```

## 기관 이식 안내

```text
다른 시군에 적용할 때는 처음부터 모든 정책 파일을 바꾸지 않아도 됩니다.
먼저 institution-profile.yaml에서 기관명, 서버, 허용 언어, DBMS, 플러그인, 라이브러리 제한만 맞추면 됩니다.
```
